
# 🐧 Linux Hero Course — systemd Logging and Service Debugging

This guide explains how Linux administrators **debug system services using systemd and journald logs**.

Understanding system logs is a critical skill for **Linux administrators, DevOps engineers, and system engineers** because most service failures can only be diagnosed through logs.

---

# 📊 systemd and journald Logging

Modern Linux distributions that use **systemd** also use a logging system called **journald**.

The journald service collects logs from:

- system services
- kernel messages
- background processes
- boot events
- applications managed by systemd

Logs can be accessed using the `journalctl` command.

---

# 🔎 Viewing All System Logs

To display all system logs stored by journald:

```bash
journalctl
````

This command shows a chronological list of log entries from system startup and service activity.

---

# 📁 Viewing Logs for a Specific Service

To display logs for a particular service:

```bash
journalctl -u nginx
```

Explanation:

| Option | Meaning                          |
| ------ | -------------------------------- |
| `-u`   | Specifies the **unit (service)** |

Example services:

```bash
journalctl -u ssh
journalctl -u docker
journalctl -u nginx
```

This command helps administrators troubleshoot service-related issues.

---

# 🔄 Following Logs in Real Time

To monitor logs live as they are generated:

```bash
journalctl -u nginx -f
```

Explanation:

| Option | Meaning                  |
| ------ | ------------------------ |
| `-f`   | Follow logs in real time |

This behaves similarly to the `tail -f` command.

It is commonly used when debugging services that are actively running.

---

# 🖥 Viewing Logs Since Last Boot

To display logs generated during the current system boot:

```bash
journalctl -b
```

This is useful for troubleshooting **startup issues and boot failures**.

---

# ⚠️ Showing Only Error Logs

To filter logs and display only error messages:

```bash
journalctl -p err
```

Explanation:

| Option | Meaning                           |
| ------ | --------------------------------- |
| `-p`   | Filter logs by **priority level** |
| `err`  | Display error-level logs          |

This helps administrators quickly identify problems.

---

# 🧠 Viewing Kernel Logs

To display logs generated by the Linux kernel:

```bash
journalctl -k
```

Kernel logs include:

* hardware detection
* driver loading
* memory management events
* kernel warnings and errors

These logs are critical when diagnosing **hardware or low-level system issues**.

---

# 🛠 Real Linux Administration Example

Consider a scenario where a service fails to start.

Example problem:

```
nginx service fails to start
```

Step 1 — Check service status:

```bash
systemctl status nginx
```

This shows:

* service state
* process information
* recent log messages

Step 2 — View detailed logs:

```bash
journalctl -u nginx
```

Possible error example:

```
port 80 already in use
```

This indicates another process is already using port 80.

The administrator can now identify and resolve the conflict.

# ⚙️ Essential systemctl Commands

System administrators frequently use the following `systemctl` commands to manage services.

Start a service:

```bash
systemctl start nginx
```

Stop a service:

```bash
systemctl stop nginx
```

Restart a service:

```bash
systemctl restart nginx
```

Check service status:

```bash
systemctl status nginx
```

Enable service at system boot:

```bash
systemctl enable nginx
```

Disable service from starting automatically:

```bash
systemctl disable nginx
```

Reload systemd configuration after modifying service files:

```bash
systemctl daemon-reload
```
